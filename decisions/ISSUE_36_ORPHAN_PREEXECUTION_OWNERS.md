# Issue #36 — orphan pre-execution owner decisions

Status: `accepted`  
Definition revision: `D1`  
Source scope: `orphan-preexecution-owners@1`

## I36-D1 — Declared owner is not optional when its prerequisite is absent

**Decision:** `[planning]` requires `[definition]`; `[plan_review]` requires `[planning]` (and thereby Definition). A missing locator is a relational invalidity and routes Recovery before unrelated downstream dispatch. A declared premium gate is not erased by falling through to an old Board.

**Why:** The current positive defect is an ignored declared state, not a request to fabricate an upstream phase.

## I36-D2 — Check relations, not unselected downstream content

**Decision:** Distinguish missing prerequisite locator checks from content validation of a selected owner. Keep local record checks when the owner is lawfully reached; do not eagerly validate all later file contents or accept/normalize an orphan.

**Why:** This preserves progressive disclosure and prevents a malformed later file from stealing an earlier legitimate owner merely because the file exists.

## I36-D3 — Preserve earlier owner and stop semantics

**Decision:** Intake/Research/tracker and an already-selected Brainstorm explicit stop retain their own precedence. #36's isolated implementation must not absorb #33; combined compatibility is a later qualification obligation against the actual composed code. On the current main baseline, a #33 stop bypass may still exist and is not certified by #36 alone.

**Why:** Separate invariants and exact subjects cannot be merged by sharing the selector.

## I36-D4 — Prefer the smallest production relational guard

**Decision:** Prefer a direct selected-workstream prerequisite check at a lawful dispatch boundary over a generic owner DAG or priority engine. Planning must justify a different mechanism if the exact failure matrix requires it.

**Why:** Two named prerequisite edges close the demonstrated failure without creating new workflow authority/state.

## I36-D5 — Positive controls are part of the contract

**Decision:** Test missing Definition, missing Planning and transitive chain with an active Board plus GREEN Definition variant; test valid active/GREEN Definition, draft/frozen/approved Planning and matched Plan Review control routes. The tests must distinguish missing locators from malformed present records and assert no downstream mutation.

**Why:** A blanket Recovery for all Planning/Review would mask the bug by breaking valid progression.

## I36-D6 — Dedicated repair and gate isolation

**Decision:** Keep the accepted Intake subject and promoted revision in this workstream. Its Definition/Planning/gates and later Card/Review remain subject-bound; the program's A/B/C and separate #32/#33 results do not transfer. No issue closure, merge or deployment is authorized here.

## I36-D7 — Escalate a genuine composition conflict

**Decision:** If Planning or later integration proves that an orphan relation cannot coexist with the already accepted #33 explicit-stop semantics without a material scope/strategy change, surface that conflict through its owning Definition/Planning cycle and applicable gates. Do not silently reverse either invariant or import #33 implementation into this Card.
