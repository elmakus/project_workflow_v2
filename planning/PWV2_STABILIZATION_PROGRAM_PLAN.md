## 6. Per-wave and final qualification protocol

For every authorized repair wave:
1. Freeze counterexamples and positive controls with exact provenance before
   claiming the repair passes; run current expected failing/passing behavior.
2. Exercise actual producers and consumers, not only handcrafted valid fixtures.
   Run cumulative production contracts, prior-wave adversarial cases and the
   closed regression baselines. A prior 271-test pass is not runtime acceptance.
3. Commit → clean clone/worktree → fresh canonical consumer; verify exact
   resolved objects/consumed bytes and semantic route/owner/effects. Separate
   selected active legacy profiles from unselected archives; never rewrite
   historical records merely for a green scan.
4. Inject interruption before/after publication, acceptance, successor selection
   and external-effect readback. Reject stale revisions/heads, mixed authority,
   lost accepted updates, double active attempts and duplicate effects. Test
   isolated contributions with reversed completion order and competing stale
   coordinators; only one lawful acceptance or fail-closed conflict is valid.
5. Publish implementation, Result and review subjects without self-reference.
   Independent required review must come from a context that neither produced
   nor repaired that exact subject. Preserve failed attempts; repaired subjects
   require fresh independence. This planner audit is not that review.
6. Record evidence only in canonical owning Results/reviews/Close records once
   materialized. Exact acceptance predicates and immutable locators outrank
   summaries, helper success, notification delivery or end-of-turn.

required, promotion, Definition, A/B/C, Prep, execution, Result, independent
Review, finalization, Close and fresh completed resume. Also cover RED repair,
